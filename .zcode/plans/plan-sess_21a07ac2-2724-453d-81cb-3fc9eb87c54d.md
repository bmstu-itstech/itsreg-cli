## Фича: визуализация графа зависимостей сценария (TUI + ASCII-рендереры)

### Контекст
itsreg-cli — Rust (edition 2024) CLI для ITS Reg API. Сценарий бота (CreateScriptRequest) уже является направленным графом: Node = состояние (вершина), Edge = переход (to: i32), Entry = точка входа (start). Графовой логики и тестов в проекте сейчас нет. Ввод — только локальный файл (повторяет FileSource из `scripts create -i`).

### 1. Зависимости (Cargo.toml, [dependencies])
- `ratatui = "0.29"` — TUI engine
- `crossterm = "0.28"` — терминальный бэкенд (raw mode, key events)

### 2. Чистая библиотека графа — `src/graph/mod.rs`
Логика без I/O, поверх существующих моделей (без дублирования):
- Трейт `StateGraph` (реализован для `CreateScriptRequest` и `Script`) — даёт `nodes()`, `entries()`.
- `GraphIndex`:
  - `by_state: BTreeMap<i32, &Node>` — поиск по id состояния
  - `order: Vec<i32>` — вертикальный «стержень»: сначала entry-состояния (отсорт. по key), затем BFS-порядок достижимых, в конце недостижимые
- Анализ (чистые функции, тестируемые):
  - `entry_states()`, `forward_edges(state)` / `back_edges(state)` (классификация по позиции в `order`; back-рёбра = циклы)
  - `cycle_states()` — DFS со стеком возврата, помечает состояния в циклах
  - `unreachable_states()`

### 3. Рендереры — `src/graph/render.rs`
Два детерминированных строковых рендерера (без I/O, со snapshot-тестами):
- **`render_spine`** (по умолчанию, «узлы вдоль вертикали»): состояния как рамки вниз по центру, соединены вертикалью; циклы (back-рёбра) как боковые дуги `╭...╮` с меткой предиката + `↺`; недостижимые — под заголовком `Unreachable`.
- **`render_tree`** (`--style tree`): DFS-дерево с `├──`/`└──`, back-рёбра как `[pred]→ N ↺` без бесконечной рекурсии.

### 4. Интерактивный TUI — `src/graph/tui.rs`
ratatui + crossterm, полноэкранный:
- Левая панель: вертикальный «стержень» (граф с прокруткой), рамки состояний, циклы подсвечены (Yellow), недостижимые — затемнены.
- Правая панель: детали выбранного узла (state, title, messages, options, edges `[predicate] op → to`, back-рёбра помечены `↺ cycle`).
- Навигация: `↑↓/jk`, `Tab` — смена панели, `q` — выход. Guard для raw mode + alternate screen, корректное восстановление при ошибках.

### 5. Интеграция в CLI — `src/main.rs`
Новая подкоманда:
```
itsreg scripts graph -i <file> [--style spine|tree] [--plain]
```
- `-i/--input <file>` (обязательно) — читает CreateScriptRequest JSON через существующий FileSource (офлайн, без сети/токена).
- `--style` (по умолчанию `spine`): `spine` | `tree`.
- `--plain` — отключает TUI, печатает рендер в stdout (для CI/скриптов и тестируемости). Без флага — интерактивный TUI.

В `main.rs`: `mod graph;`, вариант `ScriptsCommands::Graph { input, style, plain }`, диспетчеризация в `controller.show_graph(...)` (синхронно, без tokio — сеть не нужна).

### 6. Контроллер — `src/controller.rs`
```rust
pub fn show_graph(&self, src: &dyn Source, style: GraphStyle, plain: bool) -> Result<(), CliError>
```
Читает `src.input_script()` (io → CliError::IO), строит `GraphIndex`, вызывает plain-рендер или `graph::tui::run(&index, style)`; ошибки TUI → `CliError::IO`.

### 7. Тесты — `#[cfg(test)] mod tests` в `src/graph/mod.rs` (без новых dev-deps)
- Фикстура (встр. JSON): 5 узлов — entry `0 → 1 (menu)`, `1` → `2 (about)` / `3 (end)` и **цикл** `1 → 1`, плюс недостижимый `4`.
- Тесты:
  - `parse_fixture` — round-trip JSON → CreateScriptRequest → render (ловит регрессии serde).
  - `entry_states` — корни корректны.
  - `cycle_detection` — `cycle_states()` включает циклическое состояние; back-рёбра классифицированы.
  - `unreachable` — узел `4` помечен.
  - `forward_vs_back_edges` — корректная классификация.
  - `render_spine_snapshot` — содержит `↺`, `Unreachable`, стрелки.
  - `render_tree_no_infinite_recursion` — цикл `1→1` не вызывает переполнение стека, рендерится `↺`.
  - `render_tree_snapshot` — ожидаемый ASCII-вывод.
  - `order_is_stable` — `order` начинается с entry-состояний, детерминирован.
