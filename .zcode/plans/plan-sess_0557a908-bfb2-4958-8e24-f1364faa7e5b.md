# План доработки TUI: последовательный обход графа

## Контекст и решения (по ответам пользователя)

Текущий TUI (`src/graph/tui.rs`, 303 строки) — **обзорный режим**: плоский список узлов слева + детали выбранного справа, навигация стрелками по списку. Нужно **заменить** его режимом последовательного обхода графа «как пользователь идёт по боту».

Принятые решения:
1. **Старт** — меню выбора точки входа (entry) при запуске.
2. **Левая панель** — обзорный список всех блоков (как сейчас), но текущий узел обхода помечен маркером `►` и авто-скроллится к нему. Обход ведётся **выбором детей в правой панели**, не кликами по левому списку.
3. **Режим** — заменить старый плоский просмотр (TUI сразу открывается в режиме обхода).
4. **CLI `--plain`** — не трогать (рендеры `spine`/`tree` в `render.rs` остаются как есть).
5. **Path — вертикальный**: показывает 2–3 ближайших узла (предки + текущий), остальная история сворачивается в `...`, текущий узел подсвечивается.

## Модель данных (без изменений API)

`GraphIndex` (`src/graph/mod.rs`) и модели (`src/models/*`) **не меняются**. Используются:
- `idx.order()` — spine-порядок всех узлов (для левой панели)
- `idx.entries()` — точки входа (для меню)
- `idx.node(s)`, `idx.edges(s)` — узел и его исходящие рёбра
- `idx.cycle_states()` / `idx.unreachable_states()` — подсветка в обзоре (как сейчас)
- `predicate_label()` — метки предикатов

Дети узла = уникальные целевые состояния его рёбер (`edge.to`), дедуплицированные по `to`, с группировкой предикатов.

## Новая структура состояния (переписать `src/graph/tui.rs`)

```rust
enum Mode {
    PickEntry { sel: ListState },   // экран выбора точки входа
    Walk,
}

enum Focus { Overview, Children }   // Tab переключает между ними в Walk

struct ChildInfo {
    to: i32,
    title: String,
    labels: Vec<String>,   // predicate_label рёбер, ведущих к `to`
    is_revisit: bool,      // to уже есть в path (возврат ↺ по истории обхода)
}

struct App<'a> {
    idx: &'a GraphIndex<'a>,
    mode: Mode,
    path: Vec<i32>,            // история обхода; path.last() = current
    entry_key: Option<String>, // key выбранной entry (для шапки Path)
    child_state: ListState,    // выбранный ребёнок (правый низ, Walk)
    overview_state: ListState, // позиция/скролл обзора (левая панель)
    focus: Focus,
    cyclic: BTreeSet<i32>,     // как сейчас
    unreachable: BTreeSet<i32>,
}
```

Инварианты: в Walk `path` непустой; `current() = *path.last()`; `child_state` сбрасывается в 0 при каждой смене `current` и ограничен `len(children)`.

## Поток и клавиши

**Экран `PickEntry`** (при запуске):
```
┌─ Select entry point ────────────────────┐
│   start           → [1001] Открывающее  │
│ ▸ m_registration  → [28]   Продолжение  │
│   t_participant   → [5]    МГТУ?        │
│                                         │
│  ↑↓ select   Enter start   q quit       │
└─────────────────────────────────────────┘
```
- `↑↓`/`k j` — выбор entry; `Enter` → `mode=Walk`, `path=[entry.start]`, `entry_key=Some(key)`, авто-выбор current в обзоре
- `q`/`Esc` — выход

**Экран `Walk`** — 3-уровневый layout:

```
┌─ All blocks · N ─┐ ┌─ Path · start ────────┐
│ [1001] Открывающее│ │ ...                   │ ← скрытая старая история
│ [1]    152 ФЗ     │ │ [1]  152 ФЗ           │
│ [2]    Источник   │ │ [4]  Статус ◄ current │ ← подсвечен (bold+цвет)
│ [3]    ФИО        │ ├─ Current ────────────┤
│ [4]    Статус  ►  │ │ State 4   Статус      │
│ [5]    МГТУ?      │ │ Messages              │
│ ...               │ │   • Выберите статус...│
│                   │ │ Options               │
│                   │ │   ▸ Участник  ▸ Зритель│
│                   │ ├─ Children ─(focused)─┤
│                   │ │ ▸ ["Участник"]→ 31    │
│                   │ │   ["Зритель"] → 20    │
│                   │ │   ["Назад"]    → 3    │
│                   │ │   [always]     → 104 ↺│
│                   │ └───────────────────────┘
└───────────────────┘
```

**Правила рендера Path (вертикальный):**
- Узлы выводятся сверху вниз, от старых к новым (последний = current).
- Показываются **последние 3 узла** пути (`path[path.len()-3..]`). Если путь длиннее — первой строкой ставится `...` (или `↑ N more`), означающее скрытую старую историю.
- **Current** (нижний) подсвечивается: `bold` + яркий цвет (напр. `Color::Cyan`), маркер `◄ current`.
- Остальные показанные узлы — обычным стилем (серый `[id]` + title).
- Каждая строка: `[id] title` (title берётся через `idx.node(s)`).

Клавиши в Walk:
- `Tab` — переключение фокуса `Overview ↔ Children`
- Фокус **Children**: `↑↓`/`j k` — выбор ребёнка; `Enter`/`→`/`l` — переход (`path.push(to)`, current обновляется, overview скроллится к новому current, child_state сбрасывается в 0); `←`/`h`/`Backspace` — назад по пути (`path.pop`, но не ниже корня — точки входа)
- Фокус **Overview**: `↑↓`/`j k` — скролл обзора (читаемый контекст; **не двигает обход**, маркер `►` остаётся на current)
- `r`/`Home` — рестарт: `mode=PickEntry`, `path.clear()`
- `q`/`Esc` — выход

**Маркер ↺ на детях** — определяется по истории пути (`path.contains(to)`), а не по spine. Интуитивнее при пошаговом обходе: пользователь видит, что вернётся к уже пройденному узлу.

## Этапы реализации

### Шаг 1. Переписать `src/graph/tui.rs`
1. Заменить `enum Focus { Spine, Detail }` → `enum Mode` + `enum Focus { Overview, Children }`.
2. Расширить `App`: добавить `mode`, `path`, `entry_key`, `child_state`, `overview_state`; оставить `cyclic`/`unreachable`.
3. Добавить методы:
   - `current() -> Option<i32>` (`path.last().copied()`)
   - `build_children(state) -> Vec<ChildInfo>` — собрать из `idx.edges(state)`, сгруппировать по `to`, собрать `predicate_label` для каждого, `is_revisit = path.contains(to)`
   - `selected_child() -> Option<&ChildInfo>`
   - `enter_child()` / `go_back()` / `restart()`
   - `sync_overview_to_current()` — выставить `overview_state.select` на индекс `current` в `idx.order()` (авто-скролл)
4. Переписать `loop_`: dispatch по `mode` (`PickEntry` vs `Walk`) и по `focus`.
5. Переписать `draw`:
   - `PickEntry`: один `List` с записями `key → [start] title` (title через `idx.node(start)`), хелп-строка внизу.
   - `Walk`: вертикальный `Layout` справа из 3 блоков.
6. Layout правой панели: `Constraint::Length(5)` для Path (3 узла + `...` + бордюр), `Constraint::Min(8)` для Current, `Constraint::Min(4)` для Children. Точные значения подобрать при сборке.

### Шаг 2. Рендер Path (вертикальный, новый хелпер)
Новый `path_lines(idx, path, entry_key) -> Vec<Line>`:
- `let n = path.len();`
- окно показа: `start = n.saturating_sub(3)`, показываем `&path[start..]`
- если `start > 0` — первой строкой `Span::raw("...")` (или `format!("↑ {} more", start)`) в тёмно-сером
- для каждого `s` в окне: `[id]` серым + title; если `s == current` — весь спан `bold` + `Color::Cyan` и суффикс ` ◄ current`
- заголовок блока: ` Path · {entry_key} ` (если есть)

### Шаг 3. Переиспользование/адаптация хелперов
- `detail_lines` — переиспользовать для блока Current, но **без секции Edges** (рёбра показаны как Children): вынести флаг `show_edges: bool` или сделать вариант `current_node_lines`.
- `spine_line` — дополнить параметром `current: Option<i32>`: перед title ставить `► ` (текущий) или `  ` (иначе), не ломая подсветку цикл/недостижимость.

### Шаг 4. Проверка сборки и поведения
- `cargo build` (на Windows — GNU-тулчейн как в README: `cargo +stable-x86_64-pc-windows-gnu build`, либо дефолтный если работает).
- `cargo clippy` — без новых предупреждений.
- Ручной прогон: `cargo run -- scripts graph -i sample_script.json`:
  - меню выбора entry (3 шт.), выбор `start` → попадание в `1001`
  - обход: Enter по «Начать регистрацию» → переход в `1` 152 ФЗ, Path вырос, маркер `►` и авто-скролл обзора
  - углубление на 4+ шагов → проверить, что Path показывает последние 3, а верхняя история сворачивается в `...`, current подсвечен
  - назад по `←`/`Backspace` → Path сократился
  - заход в цикл (напр. `101` → `1`) → маркер `↺` на ребёнке
  - `r`/`Home` → возврат в меню entry
  - `Tab` — смена фокуса, бордюры меняют цвет
  - `q` — корректный выход, терминал восстановлен
