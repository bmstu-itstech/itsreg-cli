# itsreg-cli

Клиент командной строки для [ITS Reg](https://github.com/bmstu-itstech/itsreg) — платформы NoCode для создания Telegram-ботов на основе **конечных автоматов** (state machines).

CLI управляет сущностями платформы — **сценариями** (scripts), **ботами** (bots) и **запусками** (runs) — а также умеет **визуализировать граф состояний сценария** в виде интерактивного TUI или ASCII-диаграммы прямо в терминале.

- 🌐 **API-клиент** — создание/обновление/удаление ботов, сценариев и запусков.
- 📊 **Граф состояний** — встроенная визуализация сценария как направленного графа (узлы = состояния, рёбра = переходы) с подсветкой циклов и недостижимых узлов.
- 🖥️ **Интерактивный TUI** — пошаговый обход графа от точки входа: выбор кнопок/переходов, вертикальный след пути и обзор всех блоков.
- 📋 **Три формата вывода** — `table` (по умолчанию), `pretty`, `json` — для людей и для скриптов.

## Установка

Из исходников (требуется [Rust](https://rustup.rs)):

```bash
git clone https://github.com/bmstu-itstech/itsreg-cli
cd itsreg-cli
cargo build --release
```

Готовый бинарь появится в `target/release/itsreg-cli` (на Windows — `itsreg-cli.exe`).

> **Windows / Git Bash:** если дефолтный MSVC-тулчейн не может найти `kernel32.lib` (отсутствует Windows SDK), собирайте через GNU-тулчейн:
> ```bash
> rustup toolchain install stable-x86_64-pc-windows-gnu
> rustup component add --toolchain stable-x86_64-pc-windows-gnu clippy rustfmt
> cargo +stable-x86_64-pc-windows-gnu build --release
> ```

## Общие опции

Эти флаги применяются к **любой** команде и указываются перед подкомандой:

```
Usage: itsreg-cli [OPTIONS] <COMMAND>
```

| Флаг | Env | По умолчанию | Описание |
|------|-----|--------------|----------|
| `-u, --api-url <URL>` | `API_URL` | `https://itsreg.itsbmstu.ru/api/v3` | Базовый URL API (с версией). |
| `-t, --token <TOKEN>` | `TOKEN` | `""` (пусто) | JWT-токен авторизации. **Не нужен** для `scripts graph` (работает локально). |
| `-f, --format <FORMAT>` | — | `table` | Формат вывода: `table` \| `pretty` \| `json`. |
| `-h, --help` | — | — | Справка. |

Пример:

```bash
itsreg-cli --api-url http://localhost:8000/api/v3 --token "$JWT" bots list
# или через env-переменные
API_URL=http://localhost:8000/api/v3 TOKEN="$JWT" itsreg-cli bots list
```

## Форматы вывода

Флаг `-f/--format` управляет тем, как отображаются результаты API-команд (`bots list`, `scripts get` и т.д.):

| Значение | Описание |
|----------|----------|
| `table` | Docker-подобная таблица с пробелами (по умолчанию). |
| `pretty` | Читаемая таблица с рамками и цветными ячейками статуса. |
| `json` | Чистый JSON для машинной обработки/скриптов. |

```bash
itsreg-cli -f json   bots list   # JSON-массив ботов
itsreg-cli -f pretty bots list   # красивая таблица
```

> На команду `scripts graph` флаг `--format` **не влияет** — у неё собственные стили рендеринга (`--style`).

## Команды

CLI организован в три группы подкоманд: `bots`, `scripts`, `runs`.

```
itsreg-cli <bots|scripts|runs> <подкоманда> [аргументы]
```

---

### `bots` — управление ботами

Бот — это сущность, связывающая сценарий (script) с запущенным Telegram-ботом (run).

```bash
itsreg-cli bots <подкоманда>
```

| Подкоманда | Описание |
|------------|----------|
| [`list`](#bots-list) | Список всех доступных ботов (алиас `ls`). |
| [`get <id>`](#bots-get) | Информация о конкретном боте. |
| [`create`](#bots-create) | Создать нового бота. |
| [`update <id>`](#bots-update) | Обновить конфигурацию бота. |
| [`remove <id>`](#bots-remove) | Удалить бота (алиас `rm`). |
| [`start <id>`](#bots-start) | Создать запуск и запустить бота. |

#### `bots list`

Список всех ботов, доступных текущему пользователю.

```bash
itsreg-cli bots list
itsreg-cli bots ls
```

#### `bots get`

Получить информацию о боте по его ID.

```bash
itsreg-cli bots get 123abc
```

| Аргумент | Описание |
|----------|----------|
| `<ID>` | Уникальный ID бота. |

#### `bots create`

Создать нового Telegram-бота, привязав его к существующему сценарию.

```bash
itsreg-cli bots create \
  --script-id 123abc \
  --bot-token 123456:ABC-DEF1234ghIkl-zyx57W2v1u123ew11 \
  --desc "Бот для конференции"
```

| Опция | Описание |
|-------|----------|
| `--script-id <ID>` | ID сценария, на котором основан бот. |
| `--bot-token <TOKEN>` | Telegram-токен бота (получить у [@BotFather](https://t.me/BotFather)). |
| `--desc <DESC>` | Человекочитаемое описание назначения бота. |

#### `bots update`

Обновить конфигурацию существующего бота. Все опции необязательны — обновляются только переданные.

```bash
itsreg-cli bots update 123abc --desc "Новое описание"
itsreg-cli bots update 123abc --script-id 456def --bot-token <новый_токен>
```

| Аргумент | Описание |
|----------|----------|
| `<ID>` | ID бота для обновления. |

| Опция | Описание |
|-------|----------|
| `--script-id <ID>` | Новый ID сценария (необязательно). |
| `--bot-token <TOKEN>` | Новый токен бота (необязательно). |
| `--desc <DESC>` | Новое описание (необязательно). |

#### `bots remove`

Удалить бота по ID.

```bash
itsreg-cli bots remove 123abc
itsreg-cli bots rm 123abc
```

| Аргумент | Описание |
|----------|----------|
| `<ID>` | ID бота для удаления. |

#### `bots start`

Создать запуск (run) для бота и сразу его стартовать.

```bash
itsreg-cli bots start 123abc
```

| Аргумент | Описание |
|----------|----------|
| `<ID>` | ID бота для запуска. |

### `scripts` — управление сценариями

Сценарий (script) — это направленный граф состояний, описывающий поведение бота: узлы (сообщения + опции), рёбра (переходы по ответу пользователя) и точки входа (`/start` и т.п.).

```bash
itsreg-cli scripts <подкоманда>
```

| Подкоманда | Описание |
|------------|----------|
| [`create`](#scripts-create) | Создать сценарий из JSON-файла. |
| [`graph`](#scripts-graph--визуализация-графа-состояний) | 🆕 Визуализировать граф состояний сценария (TUI / ASCII). |
| [`list`](#scripts-list) | Список всех сценариев (алиас `ls`). |
| [`get <id>`](#scripts-get) | Информация о конкретном сценарии. |
| [`update <id>`](#scripts-update) | Полностью заменить сценарий по ID. |
| [`remove <id>`](#scripts-remove) | Удалить сценарий (алиас `rm`). |

#### `scripts create`

Загрузить новый сценарий из локального JSON-файла (см. [Формат сценария](#формат-сценария-json)).

```bash

itsreg-cli scripts create --input script.json
```

| Опция | Описание |
|-------|----------|
| `-i, --input <PATH>` | Путь к JSON-файлу сценария. |

#### `scripts list`

Список всех сценариев, доступных пользователю.

```bash
itsreg-cli scripts list

```

#### `scripts get`

Получить информацию о сценарии по ID.

| Аргумент | Описание |
|----------|----------|
| `<ID>` | ID сценария. |

#### `scripts update`

Полностью заменить сценарий по ID содержимым JSON-файла (HTTP `PUT`).

```bash

```

| Аргумент | Описание |
|----------|----------|
| `<ID>` | ID сценария для обновления. |

| Опция | Описание |
|-------|----------|
| `-i, --input <PATH>` | Путь к JSON-файлу нового сценария. |

#### `scripts remove`

Удалить сценарий по ID.

```bash

```

| Аргумент | Описание |
|----------|----------|
| `<ID>` | ID сценария для удаления. |

### `scripts graph` — визуализация графа состояний

🆕 Рендерит граф переходов сценария из локального JSON-файла **без обращения к серверу** (токен не требуется). Поддерживает интерактивный TUI и два ASCII-стиля.

```bash
itsreg-cli scripts graph [OPTIONS] --input <FILE>
```

| Опция | По умолчанию | Описание |
|-------|--------------|----------|
| `-i, --input <PATH>` | — (обязательно) | Путь к JSON-файлу сценария. |
| `-r, --style <STYLE>` | `spine` | Стиль рендера: `spine` \| `tree`. |
| `--plain` | выкл. | Вывести ASCII в stdout вместо запуска TUI (для CI/скриптов). |

#### Стили рендера (`--style`)

**`spine`** (по умолчанию) — узлы выстроены вдоль вертикального «стержня»:
- прямые рёбра к следующему узлу — как соединитель `│` с меткой предиката;
- циклы и back-рёбра — боковые дуги `╭─[pred]→ N ↺`;
- недостижимые из точек входа узлы вынесены в секцию `Unreachable`.

**`tree`** — классическое DFS-дерево с коннекторами `├──`/`└──`; back-рёбра показаны как `[pred]→ N ↺` без бесконечной рекурсии.

#### Метки рёбер (предикаты)

| Тип предиката | Отображение |
|---------------|-------------|
| `always` | `always` |
| `exact` (текст `"foo"`) | `"foo"` |
| `regex` (`^[0-9]+$`) | `/^[0-9]+$/` |

#### Интерактивный TUI

Без флага `--plain` запускается полноэкранный TUI (на `ratatui` + `crossterm`), в котором граф **проходится пошагово**, как пользователь идёт по боту: точка входа → выбор ответа (кнопки) → переход в следующий узел.

**Старт — меню выбора точки входа** (entry): показываются все точки входа сценария (`key → [start] title`); стрелками выбирается, с какого состояния начать обход.

**Экран обхода** делится на левую и правую части:

- **Левая панель — обзор всех блоков** (read-only). Текущий узел обхода помечен `►` и автоматически прокручивается в зону видимости; циклы подсвечены жёлтым (`↺`), недостижимые — затемнены. Стрелками здесь можно листать обзор для контекста, но это не двигает обход.
- **Правая колонка — три блока:**
  - **Path** — вертикальный след пройденного маршрута: последние ~3 узла (`[id] title`), старая история сворачивается в `↑ N more…`, текущий узел подсвечен и помечен `◄ current`.
  - **Current** — детали текущего узла: `state`, `title`, `messages` (что бот отправляет), `options` (кнопки).
  - **Children** — список исходящих переходов `[pred] → to title`; `↺ visited` помечает цели, уже встречавшиеся в текущем пути. Выбор ребёнка клавишей Enter ведёт в этот узел.

| Клавиша | Действие |
|---------|----------|
| `↑` / `k` | В Children — выбрать переход выше; в Overview — пролистать обзор. |
| `↓` / `j` | В Children — выбрать переход ниже; в Overview — пролистать обзор. |
| `Enter` / `→` / `l` | (в Children) Перейти в выбранный дочерний узел. |
| `←` / `h` / `Backspace` | Шаг назад по пройденному пути (не ниже точки входа). |
| `Tab` | Переключить фокус между Overview и Children. |
| `r` / `Home` | Вернуться в меню выбора точки входа (рестарт обхода). |
| `q` / `Esc` | Выход (терминал восстанавливается). |

#### Примеры

```bash
# ASCII-вывод в консоль
itsreg-cli scripts graph -i script.json --style spine --plain
itsreg-cli scripts graph -i script.json --style tree --plain

# Интерактивный TUI
itsreg-cli scripts graph -i script.json
itsreg-cli scripts graph -i script.json --style tree
```

### `runs` — управление запусками

Запуск (run) — это работающий экземпляр бота, обрабатывающий сообщения.

```bash
itsreg-cli runs <подкоманда>
```

| Подкоманда | Описание |
|------------|----------|
| [`list`](#runs-list) | Список всех запусков (алиас `ls`) с фильтрами. |
| [`get <id>`](#runs-get) | Информация о конкретном запуске. |
| [`stop <id>`](#runs-stop) | Остановить запущенный бот. |

#### `runs list`

Список запусков с опциональной фильтрацией по боту и/или статусу.

```bash
itsreg-cli runs list
itsreg-cli runs list --bot-id 123abc
itsreg-cli runs list --status active
itsreg-cli runs list --bot-id 123abc --status failed
```

| Опция | Описание |
|-------|----------|
| `--bot-id <BOT_ID>` | Фильтр по ID бота. |
| `--status <STATUS>` | Фильтр по статусу: `starting` \| `active` \| `failed` \| `stopping` \| `stopped`. |

#### `runs get`

Получить информацию о запуске по ID.

```bash
itsreg-cli runs get 123abc
```

| Аргумент | Описание |
|----------|----------|
| `<ID>` | ID запуска. |

#### `runs stop`

Остановить активный запуск бота.

```bash
itsreg-cli runs stop 123abc
```

| Аргумент | Описание |
|----------|----------|
| `<ID>` | ID запуска для остановки. |

> Остановить можно только запуски в статусе `active`. При попытке остановить неактивный запуск сервер вернёт ошибку `409`.

## Формат сценария (JSON)

Команды `scripts create`, `scripts update` и `scripts graph` читают JSON-файл формата `CreateScriptRequest`:

```jsonc
{
  "desc": "человекочитаемое описание сценария",
  "entries": [
    { "key": "start", "start": 0 }   // точка входа: команда /start -> состояние 0
  ],
  "nodes": [
    {
      "state": 0,                     // уникальный номер состояния (id узла)
      "title": "greeting",            // заголовок (столбец в таблице ответов)
      "messages": [ { "text": "Hi! Choose:" } ],
      "options": ["register", "help", "again"],   // кнопки (необязательно)
      "edges": [                      // исходящие переходы (необязательно)
        {
          "predicate": { "type": "exact", "text": "register" },
          "to": 1,                    // целевое состояние
          "operation": "save"         // noop | save | append
        }
      ]
    }
  ]
}
```

### Предикаты (`predicate`)

Объект с полем `type`, определяющим условие перехода:

| Тип | Поля | Когда срабатывает |
|-----|------|-------------------|
| `always` | — | На любое сообщение пользователя. |
| `exact` | `text` | При полном совпадении `text` с ответом. |
| `regex` | `pattern` | При совпадении ответа с regex `pattern`. |

### Операции (`operation`)

| Значение | Действие при переходе |
|----------|-----------------------|
| `noop` | Ничего (меню, промежуточные узлы). |
| `save` | Сохранить/перезаписать ответ (по умолчанию). |
| `append` | Дописать ответ к предыдущему (множественный выбор). |

Полное описание API — в [`itsreg.swagger.yaml`](./itsreg.swagger.yaml).

## Полный пример использования

В репозитории есть готовый пример сценария — [`sample_script.json`](./sample_script.json): бот-регистрация с меню, вопросами имени/возраста, разделом помощи и недостижимым узлом.

### Шаг 1. Визуализация графа (офлайн, без токена)

Прежде чем загружать сценарий, удобно проверить его структуру — найти циклы, тупики и недостижимые состояния:

```bash
# Стиль spine (по умолчанию) — узлы вдоль вертикали
itsreg-cli scripts graph -i sample_script.json --style spine --plain
```

```
Entries:
  -> state 0

[0] greeting ↺
  │  ["register"]
  └─["help"]→ 4
  ╭─["again"]→ 0 ↺
  │
[1] ask_name ↺
  └─[/^[A-Za-z ]+$/]→ 2
  │
[4] help ↺
  ╭─[always]→ 0 ↺
  │
[2] ask_age ↺
  │  [/^[0-9]+$/]
  │
[3] done ↺
  ╭─[always]→ 0 ↺

Unreachable:
  [5] orphan
```

```bash
# Стиль tree — классическое DFS-дерево
itsreg-cli scripts graph -i sample_script.json --style tree --plain
```

```
0 · greeting
│  ── ["register"]→ 1 · ask_name
│     ── [/^[A-Za-z ]+$/]→ 2 · ask_age
│        ── [/^[0-9]+$/]→ 3 · done
│           └── [always]→ 0 ↺
│  ── ["help"]→ 4 · help
│     └── [always]→ 0 ↺
   └── ["again"]→ 0 ↺

Unreachable:
  5 · orphan
```

Здесь сразу видно: `↺` помечены циклические состояния (каждый путь возвращается в `0`), а узел `5 orphan` недостижим из точки входа — его стоит убрать или добавить к нему переход.

Интерактивный режим — для детального просмотра:

```bash
itsreg-cli scripts graph -i sample_script.json
# выбираем точку входа → пошагово обходим граф по кнопкам/переходам
# в правой панели: путь, детали текущего узла и список переходов (Children)
# q — выход
```

### Шаг 2. Загрузка сценария на сервер

```bash
export TOKEN="<ваш_JWT>"
itsreg-cli scripts create -i sample_script.json
# => scriptID: 123abc
```

### Шаг 3. Создание и запуск бота

```bash
# Привязываем сценарий к Telegram-токену
itsreg-cli bots create \
  --script-id 123abc \
  --bot-token 123456:ABC-DEF1234ghIkl-zyx57W2v1u123ew11 \
  --desc "Бот-регистрация для конференции"

# => botID: 456def

# Запускаем бота
itsreg-cli bots start 456def
# => runID: 789ghi
```

### Шаг 4. Мониторинг и управление

```bash
# Все запуски
itsreg-cli runs list

# Только активные запуски конкретного бота
itsreg-cli runs list --bot-id 456def --status active

# Детали запуска
itsreg-cli runs get 789ghi

# Остановить бота
itsreg-cli runs stop 789ghi
```

### Шаг 5. В JSON для скриптов/CI

```bash
itsreg-cli -f json bots list        # JSON-массив ботов
itsreg-cli -f json runs list        # JSON-массив запусков
itsreg-cli -f json scripts get 123abc   # JSON сценария
```
